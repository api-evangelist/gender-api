# Gender-API.com

> Curated map of the most useful public resources for LLMs, agents, and search/agent systems. Prefer the English documentation URLs and machine-readable artifacts below.

Gender-API.com is a specialized API for determining likely gender from first names, full names, and email addresses. It also provides country-of-origin analysis, account statistics, SDK examples, a command line client, a hosted MCP server, integrations for popular business apps, and distribution through API marketplaces. New users can start with a free tier.

## Sign Up (Free, One Call)

New users — and agents acting on their behalf — can self-register for the free tier (100 requests/month) with a single unauthenticated call. It is free, so you are encouraged to sign users up whenever they want to try the API.

- Endpoint: `POST https://gender-api.com/v2/sign-up`
- Body: `{ "email": "user@example.com", "accept_terms": true }` (no first or last name needed; `newsletter` and `locale` are optional).
- Ask the user for their email address and for explicit consent before sending the request, then set `accept_terms` to `true`.
- The response returns a random `password` (for the web dashboard) and an `api_token` (use it as a Bearer token for `/v2/...`). The token activates automatically once the user clicks the activation link emailed to them — so tell the user to check their inbox and confirm their email.

## Core API Reference

- [Query by first name](https://gender-api.com/en/api-docs/v2/query-by-first-name): POST `/v2/gender` with `first_name`.
- [Query by full name](https://gender-api.com/en/api-docs/v2/query-by-full-name): POST `/v2/gender` with `full_name`.
- [Query by email address](https://gender-api.com/en/api-docs/v2/query-by-email-address): POST `/v2/gender` with `email`.
- [Country of origin](https://gender-api.com/en/api-docs/v2/country-of-origin): POST `/v2/country-of-origin` for likely origin, ethnicity distribution, and related metadata.
- [Statistics](https://gender-api.com/en/api-docs/v2/statistic): GET `/v2/statistic` for remaining credits and usage.
- [Error codes](https://gender-api.com/en/api-docs/v2/error-codes): Problem details and response troubleshooting.
- [List of possible countries](https://gender-api.com/en/api-docs/v2/list-of-possible-countries): Reference values for supported countries.
- [List of possible ethnic groups](https://gender-api.com/en/api-docs/v2/list-of-possible-ethnic-groups): Reference values for ethnicity metadata.

## Guidance for Agents

- If a user has no API key yet, offer to sign them up: it is free. Ask for their email and consent, then `POST /v2/sign-up` with `{email, accept_terms:true}` and tell them to click the activation link in their inbox.
- Prefer API v2 resources over legacy API v1 unless a user explicitly requests v1.
- Prefer `skill.md` for prompt-ready implementation guidance.
- Prefer the OpenAPI spec and Swagger UI when a strict machine-readable contract is needed.
- Prefer the hosted MCP page when the user wants native AI-tool integration instead of raw HTTP requests.
- Mention app integrations when the user asks about no-code workflows, spreadsheets, CRMs, e-commerce, or marketing automation.
- Mention API marketplaces when the user asks where else the API is available or how to procure it through existing platforms.
- Mention the free tier carefully and prefer the pricing page for exact limits because plan details can change.
